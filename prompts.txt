scikit-learn doesn’t have an imputer for this, so you’re right that it needs some manual handling. SimpleImputer(strategy="mean") calculates one mean per column and can’t condition on another column.

Option 1: pandas

This is the simplest option if you aren’t using a full pipeline yet:

age_means = X_train.groupby("Sex")["Age"].mean()

X_train["Age"] = X_train["Age"].fillna(X_train["Sex"].map(age_means))
X_test["Age"] = X_test["Age"].fillna(X_test["Sex"].map(age_means))

Calculate the means on the training data only, then reuse them for the test data. Using df.groupby("Sex")["Age"].transform("mean") on the full dataset would leak test data into your preprocessing.

Option 2: custom transformer

This is the better option if you’re using a Pipeline, especially with cross-validation, because the means are recalculated on the training portion of each fold:

from sklearn.base import BaseEstimator, TransformerMixin

class GroupMeanImputer(BaseEstimator, TransformerMixin):
    def __init__(self, group_col="Sex", target_col="Age"):
        self.group_col = group_col
        self.target_col = target_col

    def fit(self, X, y=None):
        self.means_ = X.groupby(self.group_col)[self.target_col].mean()
        return self

    def transform(self, X):
        X = X.copy()
        X[self.target_col] = X[self.target_col].fillna(
            X[self.group_col].map(self.means_)
        )
        return X

Put it first in the pipeline, because it needs a DataFrame with Sex still in its original form:

from sklearn.pipeline import Pipeline

pipe = Pipeline([
    ("age_impute", GroupMeanImputer()),
    ("preprocess", preprocessor),  # your ColumnTransformer that encodes Sex, etc.
    ("model", model),
])

Creating a dummyRegressor for baseline testing of my model. I am thinking of simply assuming 100% of first class passengers survived 50% of 2nd and 0% of 3rd. Do you think a regressor baseline based on class such as this is a suitable dummyRegressor for this project

Not quite: I’d use a majority-class DummyClassifier as your baseline, and keep a class-based rule only as a second comparison. There are three issues with your version:

Wrong type: Survived is a 0/1 label, so this is a classification problem. DummyRegressor predicts continuous values, while DummyClassifier is the matching tool.
Not really a dummy: dummy models ignore the input features, so they can’t use Pclass. Your idea is a hand-written rule, which is a valid baseline but needs separate code.
Numbers don’t match the data: you’ve assumed 100%, 50% and 0%, but the actual survival rates are about 63%, 47% and 24% for 1st, 2nd and 3rd class. The 50% also adds randomness to your score, whereas always predicting that 2nd class died is both repeatable and slightly more accurate.

Main problem: the model barely beats the sex rule
Your logistic regression scores 0.800 and the sex rule scores 0.787. That 1.3-point gap is well within your fold spread of ±0.022, so the notebook doesn’t yet show the model is better than that one rule. Your markdown’s “clear headroom for improvement” isn’t supported either.

To test the gap, score both on the same folds:

model_scores, sex_scores = [], []

for train_idx, val_idx in cv.split(X_train, y_train):
    X_val, y_val = X_train.iloc[val_idx], y_train.iloc[val_idx]
    pipe.fit(X_train.iloc[train_idx], y_train.iloc[train_idx])
    model_scores.append(accuracy_score(y_val, pipe.predict(X_val)))
    sex_scores.append(accuracy_score(y_val, (X_val["Sex"] == "female").astype(int)))

diff = np.array(model_scores) - np.array(sex_scores)
print(f"Mean difference: {diff.mean():.3f}")
print(f"Folds model wins/loses: {(diff > 0).sum()}/{(diff < 0).sum()}")
Use the same comparison for your FamilySize and IsAlone experiments. Repeated folds overlap, so treat the result as strong evidence rather than a formal significance test.
